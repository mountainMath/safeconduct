# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

safeconduct is an R package (built on chromote) that fetches a file or page through a real Chrome
when a server refuses plain requests, typically with a Cloudflare browser check or block page.
Nothing is simulated: a check that wants a click waits in a window for a person.

## Commands

```sh
Rscript -e 'devtools::test()'                          # all tests (offline, no Chrome needed)
Rscript -e 'devtools::test(filter = "fetch")'          # one file: tests/testthat/test-fetch.R
Rscript -e 'devtools::document()'                      # regenerate man/ and NAMESPACE from roxygen
Rscript -e 'devtools::check()'                         # R CMD check
Rscript vignettes.orig/precompute.R                    # re-knit the vignette (live network, may open Chrome)
Rscript -e 'pkgdown::build_site()'                     # site into docs/ (gitignored; CI publishes it)
```

`man/` and `NAMESPACE` are generated by roxygen (markdown on); edit the `#'` blocks in `R/`, not
the `.Rd` files.

## Vignettes are precomputed

The vignette talks to real refusing servers and can wait minutes on a check, so it is written in
`vignettes.orig/safeconduct.Rmd` (`.Rbuildignore`d) and knitted by `vignettes.orig/precompute.R`
into `vignettes/safeconduct.Rmd`, which ships with results baked in. Edit only the
`vignettes.orig/` copy, then rerun the script and commit the generated `.Rmd` with any figures.
The script forces the console tips on and clears the clearance cache and tip registry between
vignettes. Vignette downloads go to `tempdir()`.

## Architecture

The public flow (`R/fetch.R`, its header comment explains it):

1. **Probe** (`R/probe.R`): a plain curl request. `is_challenge()` (Cloudflare `cf-mitigated:
   challenge`) and `is_block()` (the "Sorry, you have been blocked" page) decide whether a browser
   is needed (`sc_needs_browser()`). If not, plain curl downloads and no browser is involved.
2. **Clearance cache**: `sc_clearance_cache`, one clearance (user agent + cookies) per host for the
   R session, reprobed before reuse and dropped when it has lapsed.
3. **Open a browser** (`sc_open_browser()` / `sc_open_attempt()` in `R/fetch.R`,
   `R/chrome.R`): Chrome launched directly with a throwaway temp profile (not
   `chromote::Chrome$new()`, which forces `--headless`), on the host's root. `sc_wait_pass()`
   decides pass/check/block from the main frame's `Network.responseReceived` document responses,
   not from a `cf_clearance` cookie.
4. **Handoff or escort**: one ranged probe tests whether curl carrying the browser's clearance is
   served. If it is, curl downloads and the clearance is cached. If not, the browser downloads
   itself (`sc_browser_download()`, landing under `tempdir()/safeconduct` and moved into place),
   or reads in-page (`sc_browser_read()`) for `read_page()`.

`headed = "auto"` (the default) runs headless first and opens a window only when headless ends on
a check or block; a check at the file's URL itself gets a longer headless wait before falling back
to a window. `useragent = TRUE` (the default) drops the word `Headless` from Chrome's user-agent
string and nothing else; `NULL` leaves it, a string is used as given. Both are function arguments
on every function that may open a browser. The long comment at the top of `R/chrome.R` records
what was tried against Cloudflare and why things are the way they are; read it before changing
browser behaviour.

`browser_session()` (`R/session.R`) keeps one browser open on a host for repeated `read_page()` /
`fetch()` calls through their `session` argument, reopening it if the window goes away and
re-passing a check the host asks for again.

`page_text()` / `page_json()` / `page_html()` (`R/parse.R`) parse a `read_page()` response
(shaped like `curl::curl_fetch_memory()`'s): charset from content-type, BOM overrides,
ISO-8859-1 read as windows-1252, a non-2xx status raised as `safeconduct_http_error`.

Cross-cutting pieces in `R/safeconduct-package.R`:
- Errors are built with `sc_error()` and classed under `safeconduct_error`
  (`safeconduct_unavailable`, `safeconduct_not_passed` with a `reason` field such as `"timeout"`
  or `"blocked"`, `safeconduct_download_error`, `safeconduct_http_error`). Control flow relies
  on catching these classes.
- Console tips (`sc_hint()`, class `safeconduct_hint`) show once per host per R session, only
  when interactive, not `quiet`, and only for calls from the console rather than another package
  (`sc_user_call()` walks the call stack). Calling packages need no configuration to silence them.
- `options(safeconduct.browser = FALSE)` is the one option, a kill switch that never opens a
  browser.

## Conventions

- Internal functions are prefixed `sc_`. Small indirections such as `sc_probe()`,
  `sc_interactive()`, `sc_display_available()`, `sc_check_wait()` and `sc_page_grace()` exist so
  tests can replace them with `testthat::local_mocked_bindings()`.
- Tests never touch the network or Chrome: `tests/testthat/helper-fake.R` provides
  `fake_session()` (a scripted stand-in for the chromote CDP surface: download and document
  events, response bodies, `Runtime.evaluate` results), `fake_chrome()`, `a_clearance()`,
  `reset_cache()` and `reset_hints()`.
- Behaviour switches go on function arguments, not `options()`, because a global option leaks
  between packages using safeconduct in one session.
- Never write scratch files to the working directory or next to the destination; use `tempdir()`.
- Never simulate a click on a check, and don't disguise the browser beyond dropping `Headless`
  from the user-agent string. If Cloudflare tightens, the window fallback is the designed answer.
- Prose (comments, roxygen, README, NEWS, messages) is plain Canadian English (`Language: en-CA`)
  in full sentences; comments explain why at some length, and user-facing messages are worded
  like the existing ones in `R/fetch.R`. Add a NEWS.md bullet for user-visible changes.
